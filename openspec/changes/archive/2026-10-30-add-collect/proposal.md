# Change: Метрики, пробы и матрица топологии

## Why
После `apply` оператор не видит, живы ли хосты и цепочка, кто сколько ходит через выход и какой протокол линка перестал отвечать. Этап 5 из `docs/design.md`: pull по SSH в локальный SQLite, чтобы TUI и скрипты читали сводку без повторных походов на хосты.

## What Changes
- Команда `collect`: по SSH с каждого хоста снимаются счётчики трафика по пользователям и outbound'ам из stats API движка (sing-box `v2ray_api`, xray `api`), состояние машины (load, память, диск, соединения, uptime, ожидающие обновления, `reboot-required`), срок сертификата и проба цепочки с временем ответа; плюс достижимость, маркер и дрейф из `plan`. Дельты счётчиков считает утилита; всё пишется в `metrics.sqlite` в каталоге состояния (в `.gitignore` состояния), ретеншн 60 дней
- Команда `probe`: проба цепочки с входов; `probe --matrix` — проверка рёбер ноутбук→вход, ноутбук→выход, вход→выход по каждому протоколу линка (tcp-коннект для reality/ws/mtg, `awg show latest-handshakes` для awg, ssh — время ответа) плюс статическая проверка из `validate`; таблица как в `screens/05-topology.html`, результат в SQLite
- Команда `status --json`: сводка для TUI и внешних скриптов из SQLite и состояния — хосты (достижимость, маркер, дрейф, машина, сертификат, проба), пользователи с трафиком за сутки/неделю/всего, outbound'ы входов, последняя проба, матрица
- Зависимость `rusqlite` (bundled), документ решения о чтении stats API в `docs/design.md`

## Capabilities

### New Capabilities
- `metrics`: сбор метрик и проб с хостов в локальную базу, матрица топологии и сводка `status --json`

### Modified Capabilities
(нет: `validate` переиспользуется как есть)

## Impact
- Модуль `metrics` в крейте, команды `collect`, `probe`, `status` в `main.rs`, `.gitignore` состояния в `ops::init`
- Зависит от `add-render` (теги outbound'ов, `cert_paths`, порт probe), `add-apply` (SSH-слой, `plan::plan`)
- На хостах нужны только `curl`, `openssl`, `awg`, `bash`, `date`, `ss`, `apt-get` — всё уже есть после bootstrap
