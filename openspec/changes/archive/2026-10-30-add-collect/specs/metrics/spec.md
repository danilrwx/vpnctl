## Purpose
Сбор метрик и проб с хостов в локальную базу оператора, проверка рёбер топологии по протоколам и машиночитаемая сводка состояния инфраструктуры для TUI и внешних скриптов. Ничего не собирается о назначениях трафика пользователей.

## ADDED Requirements

### Requirement: Сбор трафика по пользователям и outbound'ам
Система SHALL при `collect` снимать с каждого достижимого хоста накопленные счётчики трафика движка по учёткам пользователей и по outbound'ам, вычислять дельту относительно предыдущего снятия и сохранять дельту и показание счётчика локально. Сброс счётчика (перезапуск движка) MUST давать дельту, равную новому показанию, а не отрицательное число.

#### Scenario: Обычное снятие
- **WHEN** предыдущее показание счётчика учётки 1000 байт, текущее 1500
- **THEN** сохраняется дельта 500 и показание 1500

#### Scenario: Движок перезапущен
- **WHEN** предыдущее показание 1000, текущее 200
- **THEN** сохраняется дельта 200

#### Scenario: Первое снятие
- **WHEN** предыдущего показания нет
- **THEN** дельта равна текущему показанию

#### Scenario: Stats API не отвечает
- **WHEN** движок на хосте не отдаёт статистику
- **THEN** трафик за это снятие для хоста не записывается, остальные метрики хоста сохраняются, в выводе есть пометка

### Requirement: Сбор состояния машины и сертификата
Система SHALL при `collect` сохранять по каждому хосту load, память, диск корня, число установленных TCP-соединений, uptime, число ожидающих обновлений, признак `reboot-required` и число дней до истечения сертификата, путь которого соответствует рендеру хоста; с входов — результат пробы цепочки (`generate_204` через служебный socks) с кодом ответа и временем в миллисекундах. Достижимость, маркер применённого коммита и наличие дрейфа MUST браться из той же логики, что у `plan`.

#### Scenario: Хост недостижим
- **WHEN** хост не отвечает по SSH
- **THEN** для него записывается только отметка времени и причина, прочие поля пусты, остальные хосты собираются

#### Scenario: Сертификата нет
- **WHEN** файл сертификата на хосте отсутствует
- **THEN** дни до истечения не заполняются, сбор продолжается

### Requirement: Локальная база с ретеншном
Система SHALL хранить метрики в файле `metrics.sqlite` в каталоге состояния, не коммитить его (запись в `.gitignore` состояния при `init`) и удалять записи старше 60 дней при каждом `collect`; суммарный трафик «всего» MUST сохраняться отдельно и не терять данные при очистке.

#### Scenario: Старые записи
- **WHEN** в базе есть снятия 61-дневной давности и `collect` выполнен
- **THEN** этих снятий больше нет, а итог «всего» по пользователю не уменьшился

### Requirement: Проба цепочки
Система SHALL по команде `probe` выполнить с каждого входа пробу цепочки и напечатать код ответа и время; результат сохраняется так же, как при `collect`.

#### Scenario: Цепочка жива
- **WHEN** `probe` выполнен и вход получил 204 через socks
- **THEN** печатается `<вход> · 204 за <мс> мс`, запись сохранена

### Requirement: Матрица топологии
Система SHALL по `probe --matrix` проверить рёбра: ноутбук→каждый хост (tcp-коннект к портам TCP-протоколов inbound'ов и время ответа ssh), вход→выход по каждому протоколу линка (с хоста: tcp-коннект для reality и hy2, последнее рукопожатие для awg с порогом 180 с). Результат MUST печататься таблицей «ребро × протокол» с временем ответа или причиной отказа, протоколы, не описанные на ребре, помечаются прочерком; результат сохраняется локально. Статическая проверка состояния (`validate`) MUST выполняться и печататься первой.

#### Scenario: Протокол не описан
- **WHEN** в линке ru→fi нет hy2
- **THEN** в ячейке hy2 строки ru→fi стоит «— не описан»

#### Scenario: Рукопожатие awg старое
- **WHEN** последнее рукопожатие awg на линке было 10 минут назад
- **THEN** ячейка awg помечена отказом с возрастом рукопожатия

#### Scenario: Хост недостижим
- **WHEN** вход не отвечает по SSH
- **THEN** строки вход→выход для него помечены отказом «нет ответа», матрица для остальных рёбер строится

### Requirement: Сводка status --json
Система SHALL по `status --json` печатать один JSON-объект без обращения к хостам: хосты (роль, достижимость, маркер, дрейф, время ssh, машина, сертификат, последняя проба, время снятия), пользователи (включённость, трафик вверх/вниз за сутки, неделю и всего), outbound'ы по хостам за сутки, последняя проба цепочки по входам и последняя матрица. Учётки `<имя>-<режим>-<протокол>` MUST суммироваться в пользователя. Пустая база MUST давать валидный JSON с пустыми разделами.

#### Scenario: Пользователь с несколькими учётками
- **WHEN** за сутки у `brat-split-reality` 1 ГБ вниз и у `brat-full-hy2` 2 ГБ вниз
- **THEN** у пользователя `brat` в `day.down` 3 ГБ

#### Scenario: Пустая база
- **WHEN** `collect` ещё не запускался
- **THEN** `status --json` печатает объект с пустыми `hosts`, `users`, `matrix`
