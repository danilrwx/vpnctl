## ADDED Requirements

### Requirement: Рендер воспроизводим
Система SHALL формировать из одного и того же состояния побайтно одинаковые конфиги при любом числе запусков и на любой машине.

#### Scenario: Проверка воспроизводимости
- **WHEN** оператор или CI выполняет `render --check`
- **THEN** система рендерит дважды и завершается ошибкой, если хотя бы один файл различается

### Requirement: Правила маршрутизации рендерятся по группам
Система SHALL преобразовывать правила групп «для всех», «split», «full» в плоский упорядоченный список правил движка, подставляя для split/full все email'ы учёток вида `<имя>-<режим>-<протокол>` и подсети L3-пиров, и сохраняя порядок внутри группы.

#### Scenario: Пользователь split и домен из набора force-exit
- **WHEN** в группе split есть правило «набор force-exit → линк fi» ниже правила «набор ru-direct → direct»
- **THEN** в выходном конфиге правило для force-exit стоит после правила для ru-direct и перечисляет email'ы всех учёток `*-split-*` и подсеть 10.8.1.0/24

### Requirement: Подписки выводятся из состояния
Система SHALL рендерить для каждого пользователя файлы подписки по режимам в форматах base64-список, sing-box JSON и Clash YAML, содержащие только включённые протоколы входа.

#### Scenario: Отключённый протокол
- **WHEN** у входа выключен inbound hysteria2
- **THEN** ссылки hysteria2 отсутствуют во всех форматах подписок всех пользователей

### Requirement: Линк рендерится на обе стороны
Система SHALL из одного описания линка формировать outbound на хосте-источнике и inbound или пир на хосте-приёмнике с одной и той же парой ключей.

#### Scenario: Смена активного протокола линка
- **WHEN** оператор меняет активный протокол линка с awg на reality
- **THEN** меняется только маршрутизация на хосте-источнике, конфиг приёмника остаётся прежним
