# Design

## Context
Вся логика уже в библиотечном крейте: `metrics::status` даёт сводку без SSH, `render::subs` — ссылки и QR, `ops::*` возвращают сообщение коммита, `validate` → `State::save` → `git::commit` — единственный путь записи (см. `main.rs`). Долгие операции (`plan`, `apply`, `collect`, `probe`) печатают прогресс в stdout и ходят по SSH. `ratatui` 0.30 в кэше cargo, backend crossterm реэкспортируется из него. См. proposal.md — Why.

## Goals / Non-Goals
**Goals:** ни одной новой бизнес-функции — TUI только вызывает крейт; всё, что можно проверить без терминала (строки таблиц, уровень статуса, навигация, фильтр, разбор форм), — чистые функции с тестами на фикстуре `tests/fixtures/basic` и temp-базе.
**Non-Goals:** копирование в буфер обмена (ссылка видна в карточке), журнал `journalctl`, bootstrap/сертификат/обновление ОС с экрана хоста, диалоги набора и мастера хоста, графики пробы, трассировка «куда пойдёт» — отложено, в CLI всё это есть или не нужно.

## Decisions
- **Один модуль `src/tui/`, два файла.** `mod.rs` — цикл событий и рендер ratatui, `model.rs` — чистые функции: `host_rows`, `user_rows`, `rule_rows`, `matrix_rows` (строки + уровень статуса), `level_*`, `step` (навигация без переноса), `filter`, `*_form`/`parse_*` (поля формы ↔ аргументы `ops`). Альтернатива — файл на экран: больше файлов ради тех же 6 функций рендера.
- **Долгие операции — дочерний процесс `vpnctl` (`std::env::current_exe()`) с тем же `-C`,** stdout+stderr через pipe читаются в потоке и шлются по `mpsc` в цикл событий; экран 4 показывает накопленные строки. Альтернатива — переписать `plan/apply/collect` на callback вместо `println!`: правки в четырёх модулях, которые уже проверены на стенде, ради того же текста. Процесс один в каждый момент; по завершении `State` и `Status` перечитываются.
- **Формы — `Vec<(метка, значение)>` + курсор.** Значения разбираются теми же `FromStr`, что CLI (`Proto`, `Mode`, `Action`, `Group`), списки через запятую. Разбор формы в аргументы `ops` — чистая функция, тестируется без терминала; ошибки `ops`/`validate` показываются в форме. Альтернатива — виджеты чекбоксов/радио как в макетах: много кода рендера, а ввод тот же.
- **Запись = `validate` → `save` → `git::commit`,** та же последовательность, что в `main.rs`, в одной функции `commit(st, msg)`; при ошибках валидации состояние перечитывается с диска, чтобы отменить изменение в памяти.
- **Уровень статуса — enum `Level {Ok, Warn, Bad, Off}`** из чистых функций по `HostOut`/`UserOut`/`Edge`; цвет назначается только при рендере. Пороги: сертификат < 14 дн, срок пользователя < 7 дн.
- **Опрос событий с таймаутом 250 мс** (`event::poll`), чтобы строки фоновой операции появлялись без нажатий. Без tokio.
- **`clap`: `cmd: Option<Cmd>`,** `None` → `tui`. `--stub-secrets` с TUI не сочетается (ссылки были бы фальшивые) — отказ как у остальных команд.

## Risks / Trade-offs
- [Дочерний `apply` спрашивать ничего не может; при отказе guard'ов (грязное дерево, не main) текст ошибки просто попадёт в лог] → этого и достаточно: оператор видит причину и правит в git.
- [Рендер ratatui не покрыт тестами] → он тонкий (таблицы из готовых строк), проверка руками на стенде `/var/tmp/vpnctl-lab/state`.
- [QR подписки занимает ~45 строк] → показывается в карточке, при нехватке высоты обрезается; `Enter` переключает ссылку.
- [Фильтр `/` — подстрока без регистра] → ponytail: хватает для десятков пользователей.
