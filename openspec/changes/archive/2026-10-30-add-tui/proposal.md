# Change: TUI — экраны над состоянием, метриками и операциями

## Why
Всё, что умеет vpnctl, доступно только через десяток подкоманд CLI: чтобы увидеть хосты, пользователей и матрицу, оператор запускает `status`, `plan`, `probe --matrix` по очереди и держит имена хостов и индексы правил в голове. Этап 6 из `docs/design.md`: один экран с живой сводкой и те же операции по клавишам, без новой логики — TUI как тонкий слой над существующими функциями крейта.

## What Changes
- Команда `vpnctl tui` и запуск `vpnctl` без подкоманды открывают TUI в терминале на каталоге состояния (`-C`)
- Шесть экранов по `docs/design.md` §10 и макетам `screens/`: 1 Обзор (хосты, линки, сводка из `status`), 2 Пользователи (таблица трафика + карточка со ссылками подписок, tg-прокси и QR), 3 Хост (состояние, машина, сертификат, inbound'ы, линки), 4 План/Применение (вывод `plan`, построчный прогресс `apply`, `collect`, `probe --matrix`), 5 Топология (матрица рёбер по протоколам), 6 Маршрутизация (группы правил выбранного входа и наборы)
- Диалоги правила, пользователя и линка — формы из текстовых полей с тем же разбором значений, что у CLI; сохранение = операция из `ops`, валидация, запись, коммит; ошибки валидации показываются в форме, состояние не пишется
- Единая раскладка клавиш из дизайна: `1–6` экраны, `j/k`, `Enter`, `Esc`, `/` фильтр, `?` помощь, `q` выход, `p` план, `a` применить, `r` обновить метрики, `t` матрица; над объектом `n`/`e`/`x`/`D`, `J/K` для правил
- Цвета по статусу: зелёный — в норме, жёлтый — требует внимания, красный — сломано, серый — неактивно
- Долгие операции по SSH (`plan`, `apply`, `collect`, `probe --matrix`) не блокируют интерфейс: выполняются как дочерний процесс `vpnctl`, строки вывода показываются по мере появления, по завершении сводка перечитывается
- Зависимость `ratatui` (с backend crossterm)

## Capabilities

### New Capabilities
- `tui`: интерактивный терминальный интерфейс: экраны, навигация, фильтр, диалоги-формы, фоновые операции и цветовая кодировка статусов

### Modified Capabilities
(нет: `state`, `render`, `apply`, `metrics` используются как есть)

## Impact
- Новый модуль `src/tui/` (цикл и рендер ratatui + чистые функции строк таблиц, навигации, фильтра, разбора форм), подкоманда `tui` и запуск без аргументов в `src/main.rs`, `ratatui` в `Cargo.toml`, `tests/tui.rs`, README
- Зависит от всех этапов 1–5: `metrics::status`, `render::subs`, `plan`, `apply`, `ops`, `validate`, `git`
- Хостов и формата состояния не касается
