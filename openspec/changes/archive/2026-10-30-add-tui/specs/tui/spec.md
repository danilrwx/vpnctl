# Spec Delta

## Purpose
Интерактивный терминальный интерфейс оператора: сводка по хостам, пользователям, матрице и маршрутизации с одной раскладкой клавиш, диалоги-формы для правок состояния и построчный вывод долгих операций без блокировки экрана.

## ADDED Requirements

### Requirement: Запуск TUI
Система SHALL открывать TUI по команде `tui` и при запуске без подкоманды, читая состояние из каталога `-C`; при выходе (`q`) терминал MUST быть возвращён в исходный режим, в том числе при ошибке внутри интерфейса.

#### Scenario: Запуск без аргументов
- **WHEN** оператор запускает `vpnctl -C ~/vpn-state`
- **THEN** открывается экран «Обзор» для этого состояния

#### Scenario: Состояние не читается
- **WHEN** каталог не содержит состояния или секреты не расшифровываются
- **THEN** команда завершается с ошибкой в stderr, терминал не переводится в альтернативный режим

### Requirement: Экраны и единая раскладка
Система SHALL показывать шесть экранов — Обзор, Пользователи, Хост, План/Применение, Топология, Маршрутизация — переключаемых клавишами `1`–`6`; на всех экранах MUST работать `j`/`k` (строки), `Enter` (открыть), `Esc` (назад), `/` (фильтр), `?` (помощь), `q` (выход), `p` (план), `a` (применить), `r` (обновить метрики). Клавиши над объектом (`n`, `e`, `x`, `D`, `J`/`K`, `t`, `o`) действуют на экранах, где есть такой объект, и перечислены в помощи.

#### Scenario: Переключение экрана
- **WHEN** оператор нажимает `6`
- **THEN** показан экран «Маршрутизация», подсветка вкладки переходит на него, выбранная строка предыдущего экрана сохраняется

#### Scenario: Навигация по строкам
- **WHEN** выбрана последняя строка таблицы и нажата `j`
- **THEN** выбор остаётся на последней строке (без переноса по кругу)

#### Scenario: Помощь
- **WHEN** нажата `?`
- **THEN** поверх экрана показан список клавиш текущего экрана; `Esc` или `?` закрывает его

### Requirement: Обзор
Экран «Обзор» SHALL показывать ветку и HEAD репозитория состояния, чистоту дерева, таблицу хостов (роль, домен, достижимость и время ssh, применённый коммит, дрейф, проба цепочки, дни сертификата, обновления) из последней сводки метрик, линки с активным протоколом и сводку по пользователям и трафику за сутки. `Enter` на хосте открывает экран «Хост».

#### Scenario: Хост ещё не собирался
- **WHEN** по хосту нет ни одного снятия метрик
- **THEN** его строка серая, в колонках достижимости и пробы прочерки

#### Scenario: Хост недостижим
- **WHEN** последнее снятие отмечает хост недостижимым
- **THEN** строка красная, в колонке ssh — причина

### Requirement: Пользователи
Экран «Пользователи» SHALL показывать таблицу (имя, режимы, статус, срок, трафик за сутки/неделю/всего) и карточку выбранного пользователя: вход, протоколы, заметка, ссылки подписок по режимам, ссылка tg-прокси, QR выбранной ссылки. Клавиши: `n` новый, `e` править, `x` включить/выключить, `D` удалить с подтверждением, `Enter` — следующая ссылка в QR.

#### Scenario: Фильтр
- **WHEN** нажата `/` и набрано `ol`
- **THEN** в таблице остаются пользователи, чьё имя содержит `ol`; `Esc` очищает фильтр

#### Scenario: Выключение
- **WHEN** на включённом пользователе нажата `x`
- **THEN** пользователь выключен, состояние записано и закоммичено, строка стала серой

#### Scenario: У входа нет домена
- **WHEN** у входа пользователя нет домена
- **THEN** вместо ссылок в карточке показана причина, экран не падает

### Requirement: Хост
Экран «Хост» SHALL показывать выбранный хост: роль, движок, via, применённый коммит и дрейф, машину (load, память, диск, соединения, uptime, обновления, reboot), сертификат, inbound'ы (протокол, порт, вкл/выкл), исходящие линки (протоколы, активный, трафик outbound'а за сутки). `j`/`k` переключают хост, `o` на линке открывает диалог линка.

#### Scenario: Метрик нет
- **WHEN** хост ещё не собирался
- **THEN** блок «Машина» показывает прочерки, остальные блоки заполнены из состояния

### Requirement: План и применение
Экран «План/Применение» SHALL показывать построчный вывод последней операции (`plan`, `apply`, `collect`, `probe --matrix`) по мере появления строк, статус «выполняется»/«готово»/«ошибка» и экран не блокировать; `p` запускает план, `a` — применение (с подтверждением), `r` — сбор метрик, с любого экрана; одновременно выполняется не больше одной операции.

#### Scenario: План
- **WHEN** нажата `p`
- **THEN** экран 4 показывает вывод плана по мере появления, по завершении — статус «готово»

#### Scenario: Операция уже идёт
- **WHEN** во время выполнения нажата `a`
- **THEN** новая операция не запускается, в строке статуса сообщение

#### Scenario: Завершение
- **WHEN** операция завершилась
- **THEN** сводка метрик и состояние перечитаны, экраны показывают новые данные; при ненулевом коде — статус «ошибка» и последние строки stderr

### Requirement: Топология
Экран «Топология» SHALL показывать таблицу «ребро × протокол» из последней матрицы: ● с миллисекундами зелёным, ✗ красным, «не описан»/«udp» серым, время прогона; `t` запускает `probe --matrix`.

#### Scenario: Матрица не прогонялась
- **WHEN** в базе нет рёбер
- **THEN** экран показывает подсказку «t — прогнать матрицу» вместо таблицы

### Requirement: Маршрутизация
Экран «Маршрутизация» SHALL показывать для выбранного входа группы «Для всех», «split», «full» с правилами по порядку (условие, действие, вкл/выкл, заметка) и наборы доменов; `n` добавляет правило в текущую группу, `e` правит, `x` включает/выключает, `D` удаляет, `J`/`K` переставляют; каждая операция записывает и коммитит состояние.

#### Scenario: Перестановка
- **WHEN** на правиле 3 группы split нажата `K`
- **THEN** оно становится правилом 2, состояние закоммичено, выбор следует за правилом

#### Scenario: Несколько входов
- **WHEN** входов больше одного
- **THEN** `h` переключает вход, имя входа показано в заголовке

### Requirement: Диалоги-формы
Диалоги правила, пользователя и линка SHALL быть формами из текстовых полей с теми же значениями, что у CLI (списки через запятую, действие `direct|block|link:auto|link:<хост>`), `Tab`/`Shift+Tab` (`↓`/`↑`) между полями, `Enter` сохраняет, `Esc` отменяет. При сохранении система MUST выполнить операцию, валидацию, запись и коммит; при ошибке операции или валидации форма остаётся открытой с текстом ошибки, состояние не записано.

#### Scenario: Новый пользователь
- **WHEN** в форме задано имя `sergey`, режимы `split,full`, протоколы `reality,ws` и нажат `Enter`
- **THEN** пользователь создан с секретами, коммит `users: + sergey (split, full)`, карточка показывает его ссылки

#### Scenario: Ошибка валидации
- **WHEN** правило ссылается на несуществующий набор
- **THEN** форма показывает ошибку валидации, файлы состояния не изменены

#### Scenario: Редактирование
- **WHEN** на правиле нажата `e`
- **THEN** форма предзаполнена его условием, действием и заметкой

### Requirement: Цвета по статусу
Система SHALL раскрашивать строки и ячейки по статусу: зелёный — в норме, жёлтый — требует внимания (дрейф, сертификат меньше 14 дней, ожидающие обновления или перезагрузка, срок пользователя меньше 7 дней), красный — сломано (недостижим, проба не 204, ребро ✗), серый — неактивно (выключен, не собирался, не описан).

#### Scenario: Сертификат истекает
- **WHEN** до истечения сертификата хоста 9 дней
- **THEN** строка хоста жёлтая
