# Design

## Context
Экраны TUI — чистые функции в `tui::model` + рендер в `tui::mod`; формы — `Form` и `submit(form, &mut State)`. `State: Clone`, `validate` и `ops` без IO. `metrics::Status.outbounds` — хост → тег → трафик за сутки, теги `direct`, `<выход>-<протокол>`, `link-<выход>`, `exit-auto`; `Status.matrix` — рёбра последнего прогона. См. proposal.md — Why.

## Goals / Non-Goals
**Goals:** показать то, что уже есть; формы без слепого `Enter`.
**Non-Goals:** новый сбор по SSH (версии на хосте, журнал, A-записи, «был»), график проб, трассировка, JSON-превью, копирование в буфер.

## Decisions
- **Проверка на лету = `submit` на `st.clone()` + `validate`.** Состояние маленькое (десятки записей), клон на нажатие дешевле любого «частичного» разбора. Альтернатива — отдельный разбор без мутации: дублирование `submit`.
- **Трафик линка — только по тегам `<выход>-<протокол>`**, не по подстроке: `link-<выход>` и `exit-auto` — группы над теми же outbound'ами и считаются повторно.
- **Последний apply — `git tag -l 'applied/*'` отсортированный по имени** (имя = дата UTC), без разбора дат.
- **Мс линка — из `Status.matrix`** по `src == from && dst == to && proto`, без повторного SSH.

## Risks / Trade-offs
- [`submit` на клоне генерирует секреты (`user_add`) на каждое нажатие] → rand дёшев, клон отбрасывается; записи нет.
- [Превью группы правил занимает место в форме] → форма растягивается до 10 строк превью, остальное обрезается.
