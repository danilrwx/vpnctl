# Change: TUI — вторая итерация: данные из макетов, которые уже есть в крейте

## Why
Сравнение `vpnctl tui` с макетами `screens/` показало пробелы, для которых не нужен новый сбор по SSH: разбивка трафика «напрямую / через выход» и мс линков лежат в `status`, политика выхода и DNS — в `routing.yaml`, версии — в `versions.yaml`, тег последнего apply — в git. Формы вслепую: оператор видит ошибку только после `Enter`, хотя операция и валидация — чистые функции и могут работать на копии состояния при каждом нажатии.

## What Changes
- Обзор: в линках мс по протоколам из последней матрицы и политика выхода входа; в сводке трафик за сутки «напрямую / через выход» из outbound'ов; строка репо дополнена последним тегом `applied/*`
- Хост: закреплённые версии из `versions.yaml`, число пользователей на каждом inbound'е входа, политика и предпочтение выхода
- План/Применение: в заголовке экрана состояние guard'ов (ветка, чистота дерева) до запуска `a`
- Топология: над матрицей строка статической проверки (`validate`: ✓ или число ошибок)
- Маршрутизация: состав набора в условии правила (`geosite × N + M своих`), строка «если ничего не совпало — умолчание движка», блок DNS входа
- Диалоги: проверка на лету — после каждого изменения поля операция и валидация выполняются на копии состояния, внизу формы превью сообщения коммита или ошибка; для правила — как встанет группа после изменения
- Исправление: трафик линка на экране хоста считался по подстроке тега (`link-fi` + `fi-awg` дважды) — теперь только по тегам `<выход>-<протокол>`
