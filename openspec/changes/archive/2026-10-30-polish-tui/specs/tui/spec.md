# Spec Delta

## MODIFIED Requirements

### Requirement: Обзор
Экран «Обзор» SHALL показывать ветку и HEAD репозитория состояния, чистоту дерева, таблицу хостов (роль, домен, достижимость и время ssh, применённый коммит, дрейф, проба цепочки, дни сертификата, обновления) из последней сводки метрик, линки с активным протоколом, временем ответа по протоколам из последней матрицы и политикой выхода входа, последний тег `applied/*` и сводку по пользователям и трафику за сутки с разбивкой «напрямую / через выход» по outbound'ам. `Enter` на хосте открывает экран «Хост».

#### Scenario: Хост ещё не собирался
- **WHEN** по хосту нет ни одного снятия метрик
- **THEN** его строка серая, в колонках достижимости и пробы прочерки

#### Scenario: Хост недостижим
- **WHEN** последнее снятие отмечает хост недостижимым
- **THEN** строка красная, в колонке ssh — причина

#### Scenario: Разбивка трафика
- **WHEN** за сутки outbound `direct` входа дал 11 ГБ, а outbound'ы линка к выходу — 27 ГБ
- **THEN** сводка показывает «напрямую 11.0 ГБ · через выход 27.0 ГБ»

#### Scenario: Матрица не прогонялась
- **WHEN** в базе нет рёбер для линка
- **THEN** у протоколов линка нет времени ответа, строка линка показывает только протоколы и политику

### Requirement: Хост
Экран «Хост» SHALL показывать выбранный хост: роль, движок, via, применённый коммит и дрейф, машину (load, память, диск, соединения, uptime, обновления, reboot), сертификат, закреплённые версии из `versions.yaml`, inbound'ы (протокол, порт, вкл/выкл, число пользователей с этим протоколом на входе), политику и предпочтение выхода, исходящие линки (протоколы, активный, трафик outbound'ов `<выход>-<протокол>` за сутки). `j`/`k` переключают хост, `o` на линке открывает диалог линка.

#### Scenario: Метрик нет
- **WHEN** хост ещё не собирался
- **THEN** блок «Машина» показывает прочерки, остальные блоки заполнены из состояния

#### Scenario: Пользователи на inbound'е
- **WHEN** на входе два включённых пользователя с reality и один с ws
- **THEN** строка reality показывает «2 польз.», ws — «1 польз.», awg — число пиров

### Requirement: План и применение
Экран «План/Применение» SHALL показывать построчный вывод последней операции (`plan`, `apply`, `collect`, `probe --matrix`) по мере появления строк, статус «выполняется»/«готово»/«ошибка», в заголовке — состояние guard'ов применения (ветка и чистота дерева), и экран не блокировать; `p` запускает план, `a` — применение (с подтверждением), `r` — сбор метрик, с любого экрана; одновременно выполняется не больше одной операции.

#### Scenario: План
- **WHEN** нажата `p`
- **THEN** экран 4 показывает вывод плана по мере появления, по завершении — статус «готово»

#### Scenario: Операция уже идёт
- **WHEN** во время выполнения нажата `a`
- **THEN** новая операция не запускается, в строке статуса сообщение

#### Scenario: Завершение
- **WHEN** операция завершилась
- **THEN** сводка метрик и состояние перечитаны, экраны показывают новые данные; при ненулевом коде — статус «ошибка» и последние строки stderr

#### Scenario: Guard'ы до применения
- **WHEN** дерево состояния не закоммичено или ветка не main
- **THEN** заголовок экрана показывает это жёлтым до нажатия `a`

### Requirement: Топология
Экран «Топология» SHALL показывать таблицу «ребро × протокол» из последней матрицы: ● с миллисекундами зелёным, ✗ красным, «не описан»/«udp» серым, время прогона и над таблицей строку статической проверки состояния (✓ или число ошибок); `t` запускает `probe --matrix`.

#### Scenario: Матрица не прогонялась
- **WHEN** в базе нет рёбер
- **THEN** экран показывает подсказку «t — прогнать матрицу» вместо таблицы

#### Scenario: Статическая проверка
- **WHEN** состояние валидно
- **THEN** над матрицей «статическая проверка ✓ · N хостов, M линков»

### Requirement: Маршрутизация
Экран «Маршрутизация» SHALL показывать для выбранного входа группы «Для всех», «split», «full» с правилами по порядку (условие с составом набора `geosite × N + M своих`, действие, вкл/выкл, заметка), строку «если ничего не совпало — умолчание движка», блок DNS входа (резолверы direct, DoH через линк) и наборы доменов; `n` добавляет правило в текущую группу, `e` правит, `x` включает/выключает, `D` удаляет, `J`/`K` переставляют; каждая операция записывает и коммитит состояние.

#### Scenario: Перестановка
- **WHEN** на правиле 3 группы split нажата `K`
- **THEN** оно становится правилом 2, состояние закоммичено, выбор следует за правилом

#### Scenario: Несколько входов
- **WHEN** входов больше одного
- **THEN** `h` переключает вход, имя входа показано в заголовке

#### Scenario: Состав набора в правиле
- **WHEN** правило ссылается на набор `ru-direct` с 3 geosite и 14 своими доменами
- **THEN** условие показано как «набор ru-direct (geosite × 3 + 14 своих)»

### Requirement: Диалоги-формы
Диалоги правила, пользователя и линка SHALL быть формами из текстовых полей с теми же значениями, что у CLI (списки через запятую, действие `direct|block|link:auto|link:<хост>`), `Tab`/`Shift+Tab` (`↓`/`↑`) между полями, `Enter` сохраняет, `Esc` отменяет. После каждого изменения поля система SHALL выполнить операцию и валидацию на копии состояния и показать внизу формы сообщение будущего коммита или ошибку; для правила — как встанет группа после изменения. При сохранении система MUST выполнить операцию, валидацию, запись и коммит; при ошибке операции или валидации форма остаётся открытой с текстом ошибки, состояние не записано.

#### Scenario: Новый пользователь
- **WHEN** в форме задано имя `sergey`, режимы `split,full`, протоколы `reality,ws` и нажат `Enter`
- **THEN** пользователь создан с секретами, коммит `users: + sergey (split, full)`, карточка показывает его ссылки

#### Scenario: Ошибка валидации
- **WHEN** правило ссылается на несуществующий набор
- **THEN** форма показывает ошибку валидации, файлы состояния не изменены

#### Scenario: Редактирование
- **WHEN** на правиле нажата `e`
- **THEN** форма предзаполнена его условием, действием и заметкой

#### Scenario: Проверка на лету
- **WHEN** в форме правила набран несуществующий набор `nope`
- **THEN** ещё до `Enter` внизу формы ошибка валидации; после исправления — строка «коммит: routing(ru-msk-1): …»
