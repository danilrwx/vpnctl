# Project Context

## Purpose
vpnctl — TUI и CLI на Rust для одного оператора, управляющая несколькими VPS (вход в РФ + выходы за границей) через состояние в git. Рендерит конфиги xray/sing-box, веб-сервера, AmneziaWG, mtg; применяет по SSH с валидацией, пробой и откатом; выпускает пользователям подписки; собирает минимальные метрики и проверяет матрицу протоколов между узлами. См. `docs/design.md`.

## Tech Stack
- Rust 2024, `ratatui` + `crossterm` для TUI, `clap` для CLI
- `serde` + `serde_yaml` для состояния, `minijinja` для шаблонов, `rusqlite` для метрик
- Внешние процессы: `ssh` (с `-J`, ControlMaster), `git`, `sops`/`age`, `xray`/`sing-box` (`-test`)
- Целевые хосты: Debian stable; sing-box (xray по полю `engine` хоста), Caddy (ACME встроен), amneziawg-dkms, mtg

## Project Conventions

### Code Style
- `cargo fmt`, `cargo clippy -D warnings`
- Ошибки через `anyhow` на границе CLI, `thiserror` в библиотечных модулях
- Логика в библиотечном крейте `vpnctl-core`, TUI и CLI — тонкие фронты над ним

### Architecture Patterns
- Источник истины — файлы состояния в git; TUI их только редактирует и коммитит
- Рендер чистый и детерминированный: без времени, случайностей, с сортированными ключами
- Секреты только через sops; расшифровка в памяти на время рендера/apply
- Применение push по SSH с ноутбука оператора; CI без секретов только валидирует
- Никаких демонов на хостах кроме целевых служб (xray/sing-box, caddy, awg, mtg)

### Testing
- Юнит-тесты рендера на фикстурах состояния: снапшоты конфигов (`insta`)
- Проверка воспроизводимости: два рендера одного состояния идентичны побайтно
- Интеграционные тесты применения — на локальных контейнерах с sshd (отложено)

### Git Workflow
- `main` — единственная применяемая ветка; apply отказывается с грязного дерева
- Тег `applied/<дата>` на серию после успешного apply
- Коммиты подписываются ключом на YubiKey (опционально)

## Domain Context
- Вход (entry/джамп-хост) в РФ терминирует все пользовательские протоколы и маршрутизирует: российское напрямую, остальное в линк к выходу
- Режимы пользователя: split / full; для учёток движка — суффиксом режима в email `<имя>-<режим>-<протокол>`, для L3-пиров — подсетью
- Линк — направленная связь между нодами с несколькими протоколами и политикой выбора
- Подписка — статический файл на домене входа, обновляется клиентом сам

## Important Constraints
- Домен в ссылках, никогда IP: переезд ноды должен быть невидим пользователям
- Не хранить адреса назначения пользователей и access-логи
- sshd не входит в область управления; джамп применяется последним
- Сертификаты и обновления ОС — среда выполнения на хосте, не часть состояния

## External Dependencies
